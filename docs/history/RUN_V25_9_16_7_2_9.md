# RUN v25.9.16.7.2.9 — AP Campus Map Payload + STT Sweep

## Mục tiêu

Bản này sửa lỗi AP CMS `get-campus` trả data dạng object map nhưng backend chỉ đọc dạng list, làm `/premises`/campus sync báo sai: `AP get-campus không trả cơ sở nào` dù `curl` có dữ liệu.

Đồng thời rà lại toàn bộ bảng FE có header `STT` nhưng thiếu cell STT trong body.

## Thay đổi chính

- `APAcademicClient._extract_list_response` hỗ trợ payload dạng:

```json
{"data":{"ph":"CĐ Hà Nội","ps":"CĐ Hồ Chí Minh"}}
```

và normalize thành list campus chuẩn:

```json
[{"campus_code":"ph","campus_name":"CĐ Hà Nội"}]
```

- Sửa các bảng còn lệch STT:
  - `/ap-sync` bảng Kết quả gần nhất
  - `/teacher-management/teachers/{id}/classes`
  - Assignment workflow trong `/student-management/classes/{classId}`

- Thêm test backend để chống regression AP object-map payload.
- Thêm test quét TSX: mọi table có header `STT` phải có `stt-cell` trong body.

## Deploy

```bash
cd /opt/ai-server

unzip -o ai-server-openedx-v25.9.16.7.2.9-ap-campus-map-stt-sweep.zip -d /tmp/ai-server-v25.9.16.7.2.9

rsync -a --delete /tmp/ai-server-v25.9.16.7.2.9/ai_server_openedx_v25_9_16_7_2_9/ /opt/ai-server/

docker compose -f docker-compose.prod.yml --env-file .env.production build backend frontend worker beat
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend frontend worker beat
```

Cập nhật `.env.production`:

```env
APP_VERSION=25.9.16.7.2.9
```

## Kiểm tra sau deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production logs -n 200 backend
```

Vào `/premises` hoặc `/ap-sync` bấm đồng bộ danh sách cơ sở. Poly phải ra 12 cơ sở, PTCĐ phải ra 21 cơ sở theo AP CMS.
