Thêm các index phụ an toàn cho hierarchy, quiz history và audit:


PostgreSQL dùng `CREATE INDEX CONCURRENTLY` để tránh lock ghi/đọc lâu khi bảng lớn. SQLite/dev fallback sang `CREATE INDEX IF NOT EXISTS`.

### 1.2. Thêm DB pool config

Backend dùng các giá trị này trong `backend/app/db/session.py` khi DATABASE_URL là PostgreSQL.

### 1.3. Thêm statement timeout

Mỗi PostgreSQL connection được set:

```sql
statement_timeout = DB_STATEMENT_TIMEOUT_MS
```

Mặc định production là `5000ms`. Mục tiêu là chặn query lỡ tay scan toàn bảng quá lâu khi dữ liệu lớn.

### 1.4. Backend production multi-worker

`docker-compose.prod.yml` chuyển backend sang Gunicorn + UvicornWorker:

```bash
gunicorn app.main:app \
  -k uvicorn.workers.UvicornWorker \
  -w ${WEB_CONCURRENCY:-2} \
  -b 0.0.0.0:8000 \
  --forwarded-allow-ips='*' \
  --timeout ${WEB_TIMEOUT_SECONDS:-120}
```

Thêm dependency:

```text
gunicorn==23.0.0
```

Env production:

```env
WEB_CONCURRENCY=2
WEB_TIMEOUT_SECONDS=120
CELERY_CONCURRENCY=4
```

## 3. Env cần thêm/sửa trong `.env.production`

```env
APP_VERSION=25.9.15.6.32-database-scale-foundation
DB_POOL_SIZE=10
DB_MAX_OVERFLOW=20
DB_POOL_TIMEOUT=30
DB_POOL_RECYCLE=1800
DB_STATEMENT_TIMEOUT_MS=5000
WEB_CONCURRENCY=2
WEB_TIMEOUT_SECONDS=120
CELERY_CONCURRENCY=4
```

Nếu PostgreSQL `max_connections` thấp, cần tính:

```text
max_connections cần >
backend WEB_CONCURRENCY * (DB_POOL_SIZE + DB_MAX_OVERFLOW)
+ worker process count * (DB_POOL_SIZE + DB_MAX_OVERFLOW)
+ admin/psql/maintenance buffer
```

Với default hiện tại:

```text
backend: 2 * (10 + 20) = 60
worker:  1 process * (10 + 20) = 30
buffer:  20+
=> nên có ít nhất khoảng 110-120 connections, hoặc giảm DB_MAX_OVERFLOW nếu server nhỏ.
```

Server nhỏ nên dùng:

```env
DB_POOL_SIZE=5
DB_MAX_OVERFLOW=10
WEB_CONCURRENCY=2
CELERY_CONCURRENCY=2
```

### 4.4. EXPLAIN query mở chapter/bank

Thay `BANK_VERSION_ID` thật:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec postgres psql -U ai_user -d ai_openedx -c "
EXPLAIN (ANALYZE, BUFFERS)
SELECT id, status, difficulty, created_at
FROM ai_questions
WHERE bank_version_id = 'BANK_VERSION_ID'
  AND status = 'approved'
ORDER BY created_at DESC, id DESC
LIMIT 50;
"
```
