# v25.9.16.5.41 — Async Material Upload + AP Sync Job Recovery

## Mục tiêu

- Trả upload tài liệu về đúng kiến trúc job nền vì tách tài liệu là tác vụ nặng.
- Không chạy tách tài liệu inline trong backend ở production mặc định.
- Đồng bộ AP `/ap-sync` chuyển sang job Celery có trạng thái backend, F5 hoặc mở máy khác vẫn thấy tiến trình đang chạy.
- Giữ UI AI Server nền v27 + loading cục bộ đã chốt ở các bản trước.

## Thay đổi chính

### 1. Upload tài liệu chạy bằng job nền

`BANK_MATERIAL_EXTRACT_INLINE_ENABLED` mặc định đổi thành `false`.

Luồng upload:

1. Backend nhận file, preflight định dạng/kích thước.
2. Lưu file vào `LOCAL_STORAGE_PATH/question-bank/_pending-operation-files`.
3. Tạo `BankOperationJob(operation_type='material_extract')`.
4. Enqueue Celery task `bank_material_extract_task`.
5. UI đọc job từ backend để hiện trạng thái `queued/running/completed/failed`.

Yêu cầu production:

```env
LOCAL_STORAGE_PATH=/app/.runtime
BANK_MATERIAL_EXTRACT_INLINE_ENABLED=false
```

`docker-compose.prod.yml` đã mount chung `runtime_data:/app/.runtime` cho backend và worker. Nếu triển khai ngoài compose, phải đảm bảo backend và worker dùng chung storage.

### 2. Đồng bộ AP chạy bằng job

Trang `/ap-sync` không gọi blocking `POST /api/academic/sync/ap` nữa. UI dùng:

- `POST /api/academic/sync/ap/jobs`
- `GET /api/academic/sync/ap/jobs?status=active`
- `GET /api/academic/sync/ap/jobs/{run_id}`

Job được lưu trong `academic_sync_runs` với `status=queued/running/completed/failed`, `counters_json.progress` chứa tiến độ và nhãn hiển thị.

### 3. F5/máy khác vẫn thấy tiến trình

Không dùng `localStorage` để lưu trạng thái tác vụ dài. Khi mở `/ap-sync` hoặc `/bank/chapters/{id}`, frontend đọc job đang `queued/running` từ backend.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

Không cần Alembic vì không thêm bảng/cột.

## Kiểm tra worker

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production ps worker redis

docker logs ai-worker --tail=100
```

## Test upload tài liệu

1. Vào `/bank/chapters/{chapterId}`.
2. Upload tài liệu.
3. Kiểm tra nút/khu vực tài liệu hiện `Đang up tài liệu`.
4. F5 trang.
5. Trạng thái job vẫn hiện nếu còn queued/running.
6. Vào `/bank/history` hoặc trang jobs để xem `Tách tài liệu` chạy từ queued → running → completed.

## Test AP sync

1. Vào `/ap-sync`.
2. Chạy đồng bộ AP.
3. F5 ngay khi đang chạy.
4. Banner `Hệ thống đang đồng bộ AP` phải hiện lại từ backend.
5. Mở browser/máy khác cùng tài khoản admin, vào `/ap-sync`, trạng thái vẫn hiện nếu job còn chạy.
