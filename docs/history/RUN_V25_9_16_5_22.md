# v25.9.16.5.22 — Auto Retire Carry-over Questions When Materials Change

## Mục tiêu

Khi tạo version môn mới từ version cũ, câu hỏi clone vẫn được giữ trạng thái `Đã chấp nhận`. Khi người dùng xóa hoặc upload tài liệu mới, hệ thống tự kiểm tra lại câu hỏi clone với toàn bộ tài liệu hiện tại của bài. Câu nào không còn căn cứ trong tài liệu hiện tại thì tự loại khỏi version mới bằng `retired`, không xóa cứng.

## Điểm chính

- Không so theo tên file.
- Nếu nội dung cũ chuyển sang file mới nhưng vẫn còn trong bộ tài liệu, câu hỏi vẫn giữ.
- Chỉ retire câu carry-over/cloned đang approved/published, không động vào câu tự sinh mới.
- Câu bị retire được gỡ khỏi Release nháp/chưa publish.
- Có API chạy lại thủ công: `POST /api/question-bank-v2/bank-versions/{bank_version_id}/materials/recheck-carry-over`.
- Sửa lỗi migration DB trắng bị duplicate table do `0001_initial_schema` tạo schema hiện tại trước các migration sau.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend
docker compose -f docker-compose.prod.yml --env-file .env.production run --rm backend alembic upgrade head
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

Nếu trước đó đã `down -v` và DB trắng, vẫn dùng `alembic upgrade head` bình thường. Không cần `stamp 0017` nữa.

## Test nghiệp vụ

1. Tạo version môn mới từ version cũ.
2. Kiểm tra câu hỏi clone vẫn là `approved`.
3. Xóa tài liệu cũ hoặc upload tài liệu mới.
4. Hệ thống trả message dạng: `Đã kiểm tra lại câu hỏi clone: giữ X, tự loại Y câu...`.
5. Vào danh sách câu hỏi, các câu không còn căn cứ phải chuyển `retired` và không còn nằm trong danh sách publish/release.

## Kiểm tra tay nếu cần

```bash
curl -k -X POST "https://<AI_API_DOMAIN>/api/question-bank-v2/bank-versions/<BANK_VERSION_ID>/materials/recheck-carry-over" \
  -H "Authorization: Bearer <TOKEN>"
```
