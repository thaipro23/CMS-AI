# RUN v25.9.16.7.2.6 — Production Workflow Polish

## Mục tiêu bản này

Làm tiếp phần production test sau bản 7.2.5, tập trung vào các lỗi vận hành và UX người dùng đã báo:

1. `/semesters` bấm sửa học kỳ phải fill đúng block/tuần học của học kỳ đang sửa.
2. Xóa bài/chapter trống không còn bị chặn bởi shell `bank version` rỗng hoặc metadata runtime.
3. Bank multipage bỏ wording xấu: `Chưa làm`, `Chưa làm hết`, `Đã public thư viện`.
4. Viền/card trạng thái Bank có màu rõ, không bị xám hết.
5. `/jobs` và `/audit` tách vai trò rõ hơn; Jobs mặc định hiện cả AP sync gần đây, không chỉ job đang chạy.
6. Giữ scrollbar dọc ổn định, giảm tình trạng trang mất thanh cuộn sau route/modal transition.

## Đã sửa

### 1. `/semesters` edit fill đúng dữ liệu

File:

```text
frontend/app/semesters/page.tsx
```

Thay cách lấy `blocks.slice(0, 2)` bằng resolver `pickBlocksForTermForm()`:

- Ưu tiên block active.
- Ưu tiên đúng `sort_order = 1/2`.
- Fallback nhận diện `Block 1`, `Block 2` từ `block_code`/`block_name`.
- Không lấy nhầm block cũ/đã xóa khi backend trả thứ tự không ổn định.

### 2. Xóa chapter trống không bị chặn bởi bank version rỗng

File:

```text
backend/app/services/question_bank_service.py
```

`_delete_empty_bank_versions_for_chapter()` giờ chỉ coi các dữ liệu sau là nội dung thật cần chặn xóa:

```text
materials, chunks, concepts, families, questions, releases
```

Các dữ liệu runtime/metadata không còn chặn chapter trống:

```text
jobs, search documents, diff rows, based_on shell references
```

Khi chapter không có nội dung thật, hệ thống tự detach/delete metadata này rồi xóa chapter. Thông báo lỗi xóa cũng đổi sang dễ hiểu hơn, không còn làm người dùng hiểu nhầm rằng “bank version rỗng” là nội dung thật.

### 3. Bank wording + màu trạng thái

File:

```text
frontend/app/bank/_components/shared.tsx
frontend/app/bank/_components/pages/*.tsx
frontend/app/globals.css
```

Đổi wording:

```text
Chưa làm        -> Chưa có dữ liệu
Chưa làm hết    -> Cần hoàn thiện / Cần xử lý tiếp
Đã public thư viện -> Đã đưa lên CMS
```

Thêm class trạng thái rõ:

- `status-published`: xanh lá.
- `status-ready`: xanh dương.
- `status-incomplete`: cam.
- `status-danger`: đỏ.
- `status-empty`: xám nhưng có viền trái rõ.

### 4. `/jobs` và `/audit` rõ ràng hơn

Files:

```text
frontend/app/jobs/page.tsx
frontend/app/audit/page.tsx
```

Jobs:

- Tiêu đề đổi thành `Jobs / Việc xử lý`.
- Mô tả rõ đây là job chạy nền.
- Status mặc định là `Tất cả`, nên vào Jobs sẽ thấy AP sync vừa chạy xong, không bị ẩn vì mặc định chỉ xem `Đang chạy`.
- KPI thứ 4 đổi thành `AP sync gần đây`.

Audit:

- Tiêu đề đổi thành `Audit / Nhật ký hoạt động`.
- Mô tả rõ Audit là thao tác/lỗi nghiệp vụ, còn job/progress xem ở Jobs.
- Bổ sung label cho các action academic/analytics.

### 5. Scrollbar ổn định hơn

File:

```text
frontend/app/globals.css
```

Thêm guard cuối file:

```css
html { overflow-y: scroll; scrollbar-gutter: stable; }
```

## Deploy production

```bash
cd /opt/ai-server

unzip -o ai-server-openedx-v25.9.16.7.2.6-production-workflow-polish.zip -d /tmp/ai-server-v25.9.16.7.2.6
rsync -a --delete /tmp/ai-server-v25.9.16.7.2.6/ai_server_openedx_v25_9_16_7_2_6/ /opt/ai-server/

# giữ nguyên .env.production thật, không copy đè secret
docker compose -f docker-compose.prod.yml --env-file .env.production build backend frontend worker beat
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend frontend worker beat
```

## Verify sau deploy

```bash
cd /opt/ai-server

# Backend compile nhanh
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend python -m py_compile app/services/question_bank_service.py app/services/learning_analytics/analytics_core_service.py app/api/routes/academic.py

# Backend log không có crash
docker compose -f docker-compose.prod.yml --env-file .env.production logs -n 150 backend
```
