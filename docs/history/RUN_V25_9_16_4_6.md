# v25.9.16.4.6 — CMS SSO Callback Loop Hotfix

## Scope

This hotfix fixes the CMS/Open edX SSO browser loop on:

```text
/auth/cms-callback?ticket=...
```

The issue was caused by two problems:

1. The callback React effect could process the same one-time ticket repeatedly after auth context state changed.
2. In production, the frontend did not treat an HttpOnly cookie session as authenticated after page refresh, so AppShell could immediately start the CMS bridge again.

## What changed

- `frontend/app/auth/cms-callback/page.tsx`
  - Adds a one-ticket guard with `useRef`.
  - Uses `router.replace('/bank')` after successful exchange.
  - Does not leave the one-time ticket in browser history.

- `frontend/context/AppContext.tsx`
  - Adds production cookie-session probing through `/api/rbac/me` with `credentials: include`.
  - `isAuthenticated` now accepts either in-memory token or verified HttpOnly cookie session.
  - AppShell waits until the auth probe finishes before auto-starting CMS bridge.

- `frontend/components/layout/AppShell.tsx`
  - Sidebar session status now uses effective authenticated state.
  - Footer version updated to `v25.9.16.4.6`.

## Deploy

No database migration.

Frontend-only rebuild is usually enough:

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate frontend
```

If backend image/config was also changed, rebuild backend too:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production build backend frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend frontend
```

## Required UAT env check

Current UAT URL is HTTP:

```text
http://ai.cms-test.poly.edu.vn
```

For HTTP UAT, use:

```env
AUTH_COOKIE_SECURE=false
AUTH_COOKIE_SAMESITE=lax
AUTH_COOKIE_DOMAIN=
```

If `AUTH_COOKIE_SECURE=true` on HTTP, Chrome will not save the AI session cookie. Login may work for the current SPA state, but refresh will start CMS bridge again.

For HTTPS production, use:

```env
AUTH_COOKIE_SECURE=true
AUTH_COOKIE_SAMESITE=lax
AUTH_COOKIE_DOMAIN=.cms-test.poly.edu.vn
```

Only set `AUTH_COOKIE_DOMAIN` if all AI/API domains share that parent domain and CORS/cookie settings are correct.

## Test checklist

1. Open AI Server in incognito.
2. Let it redirect to CMS bridge.
3. After callback success, it must go to `/bank`, not stay at `/auth/cms-callback?ticket=...`.
4. The browser URL must not contain `ticket=` after success.
5. Refresh `/bank`; it must not bounce repeatedly back to CMS if cookie is saved.
6. In Chrome DevTools → Application → Cookies, verify `ai_openedx_access_token` exists for the AI/API domain when using cookie SSO.
