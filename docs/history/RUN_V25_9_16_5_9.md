# v25.9.16.5.9 — Open edX Connector Runtime CSRF Exempt Hotfix

This release fixes the HTML `403 Forbidden` returned by Open edX for server-to-server runtime connector POST endpoints, especially:

```text
/api/ai-connector/v1/users/resolve
/api/ai-connector/v1/course-enrollment/enroll
/api/ai-connector/v1/class-analytics
```

## Cause

The request reached Open edX Django, but `student_insight.py` runtime endpoints were not explicitly marked `csrf_exempt`. Django CSRF middleware can reject POST requests before the connector HMAC validator runs, returning an HTML 403 page.

## Fix

All runtime connector views in `openedx_connector_plugin/openedx_ai_connector/student_insight.py` are now `@csrf_exempt` while still requiring server-to-server HMAC.

## Deploy AI Server

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

## Update Open edX plugin

The important part is updating the plugin inside Tutor/Open edX, not only AI Server. Rebuild/restart LMS/CMS after copying the new plugin code. Use your existing deployment method for `openedx_connector_plugin`; typical flow:

```bash
# Example only: adapt path to your Open edX/Tutor plugin workflow
# Copy openedx-connector-plugin from this package into the Open edX build context
# Then rebuild/restart LMS/CMS images/containers.

tutor local restart lms cms lms-worker cms-worker
```

If the plugin is baked into the Open edX Docker image, restart alone is not enough; rebuild the image first.
