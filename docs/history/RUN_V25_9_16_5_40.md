# RUN v25.9.16.5.40 — AP Block Cache + Material Upload Inline Hotfix

## Mục tiêu

Bản này giữ UI AI Server nền v27/v39, không đổi MFE/timer/reset. Sửa 2 vấn đề vận hành:

1. AP `/get-data-cms` có `term.block[]` và `class[].block_id`: AI Server cập nhật `/semesters` khi term/block từ AP khác dữ liệu hiện có, nhưng không lặp lại upsert block cho từng subject trong cùng một lượt sync.
2. Upload tài liệu Bank bị treo `Tách tài liệu / Đang chờ`: material extraction chạy trực tiếp trong backend mặc định, không phụ thuộc Celery worker. Operation Job vẫn được ghi lại để audit.

## Thay đổi chính

### 1. Block/kỳ học AP

- Thêm signature cho master data AP term/block: term id/name/date + danh sách block id/name/date.
- Nếu signature giống lần kiểm gần nhất và còn trong TTL, AI Server chỉ load block hiện có để map class, không upsert lại `/semesters` nhiều lần.
- Nếu AP trả signature khác, AI Server cập nhật term/block ngay.
- Khi class có `block_id`, ưu tiên map theo `class.block_id` -> `term.block[].id`.
- Nếu thiếu hoặc không khớp `block_id`, fallback theo ngày lớp `start_date/end_date` và block `start_day/end_day`.
- Nếu vẫn không map được nhưng AP có `block_id`, tạo block placeholder để lớp không bị mất dữ liệu, đồng thời admin nhìn thấy ở `/semesters` để sửa.

Env mới:

```env
ACADEMIC_AP_TERM_BLOCK_REFRESH_TTL_SECONDS=3600
```

Đặt `0` nếu muốn luôn kiểm/upsert theo payload AP.

### 2. Upload tài liệu không còn kẹt queued

- Env mới:

```env
BANK_MATERIAL_EXTRACT_INLINE_ENABLED=true
```

Mặc định `true`.

- Khi upload tài liệu, backend tạo `BankOperationJob` rồi chạy `bank_material_extract_task.apply(...)` trực tiếp trong backend process.
- Nếu thành công, job chuyển `completed` ngay.
- Nếu lỗi extractor, job chuyển `failed` ngay với lỗi cụ thể.
- Nút `Chạy lại` với job `material_extract` cũng chạy inline nếu setting này bật.
- Các job nặng khác như tạo câu hỏi, publish, tạo quiz vẫn dùng Celery.

Nếu muốn quay lại chạy upload qua Celery:

```env
BANK_MATERIAL_EXTRACT_INLINE_ENABLED=false
```

Khi đó cần bảo đảm backend/worker dùng chung `LOCAL_STORAGE_PATH=/app/.runtime` và worker đang tiêu thụ Redis.

## Deploy

Backend có thay đổi, nên build backend + worker + frontend cho an toàn:

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

Không cần Alembic vì không thêm bảng/cột.

## Kiểm tra sau deploy

### Kiểm tra block

Chạy sync AP cho một subject có dữ liệu như `block_id=132`.

Kỳ Summer 2026 phải có:

```text
Block 1 -> ap_block_id 132
Block 2 -> ap_block_id 133
```

Lớp có `block_id=132` phải nằm ở Block 1.

### Kiểm tra upload tài liệu

1. Upload file vào một Bank Version.
2. Mở `/bank/jobs`.
3. Job `Tách tài liệu` không được nằm mãi ở `Đang chờ`.
4. Kết quả hợp lệ:
   - `Hoàn tất` nếu extractor đọc được file.
   - `Thất bại` kèm lỗi cụ thể nếu file không đọc được hoặc thiếu file tạm.

### Xử lý 2 job cũ đang kẹt

Sau deploy bản này, bấm `Chạy lại` ở 2 job `Tách tài liệu` đang `Đang chờ`.

Nếu file tạm vẫn còn trong runtime shared path, job sẽ chạy hoàn tất.
Nếu file tạm đã mất do container/volume khác nhau, job sẽ chuyển `Thất bại` với thông báo rõ ràng, lúc đó cần upload lại tài liệu.
