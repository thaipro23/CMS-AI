# RUN v25.9.16.7.2.3 — Full Test Rollout Async Sync Hotfix

## Mục tiêu

Sửa lỗi job đồng bộ lớp thất bại:

```text
name 'batch_learning_counts' is not defined
```

Nguyên nhân: trong luồng **Đồng bộ full CMS / enrollment** có một đoạn cộng thống kê `batch_learning_counts` bị đặt nhầm từ luồng **Cập nhật điểm**. Luồng enrollment không gọi `class_analytics_payload`, nên biến này không tồn tại.

Bản này xóa đoạn dùng biến không thuộc luồng enrollment. Không đổi database schema, không thêm migration.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

## Migration

Không có migration mới. Nếu trước đó chưa chạy migration analytics core thì chạy:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend alembic upgrade head
```

## Kiểm tra lỗi đã hết

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production logs -n 300 worker | grep -Ei "batch_learning_counts|academic.class_sync.async|failed|error"
```

Không còn dòng:

```text
name 'batch_learning_counts' is not defined
```

## Kiểm tra tracking log mount

Trên host Open edX/Tutor, lấy đúng printroot:

```bash
tutor config printroot
ls -lah "$(tutor config printroot)/data/lms/logs"
```

Nếu có `tracking.log`, đặt trong `.env.production`:

```env
OPENEDX_TRACKING_LOG_HOST_DIR=<kết_quả_tutor_printroot>/data/lms/logs
OPENEDX_TRACKING_LOG_PATH=/openedx-data/lms/logs/tracking.log
ANALYTICS_INGEST_ENABLED=true
ANALYTICS_INGEST_SCHEDULER_ENABLED=true
```

Sau đó recreate backend/worker để compose mount lại volume.

## Lưu ý môi trường test ít data

```env
ANALYTICS_ROLLOUT_ENABLED=true

```

Nhưng vẫn có guard chống job trùng, giới hạn backfill/export và kiểm tra monitoring.
