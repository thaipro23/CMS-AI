# v25.9.16.2.21 — Academic Logic Quality Hardening

## Mục tiêu

Bản này không thêm màn lớn mới. Trọng tâm là rà soát và sửa lỗi logic có thể làm sai dữ liệu khi tiếp tục phát triển luồng:

```text
AP Sync → Màn Môn → Màn Lớp → Chi tiết lớp → Kiểm tra đồng bộ CMS
```

## Lỗi logic đã sửa

### 1. AP Sync tạo trùng học kỳ

Bản cũ có thể tạo term code dạng:

```text
SUMMER_2026:poly
```

thay vì dùng kỳ đã tạo ở `/semesters`:

```text
Summer 2026
```

Hậu quả: `/ap-sync` chạy xong nhưng `/student-management` chọn `Summer 2026` lại không thấy lớp/môn vì class nằm ở term duplicate.

Bản này sửa để AP sync ưu tiên reuse term theo `term_code/term_name + branch` đã tạo ở `/semesters`.

### 2. AP Sync tạo thừa block

Bản cũ có thể tạo thêm block theo AP id như `132`, `133`, làm `/semesters` có hơn 2 block.

Bản này sửa để reuse block theo tên `Block 1`/`Block 2`, chỉ lưu AP id vào `ap_block_id`.

### 3. Class cũ không tự chuyển về term/block chuẩn

Nếu class đã từng sync vào term duplicate, lần sync sau tìm thấy class theo `ap_class_id` nhưng không cập nhật `term_id/block_id/subject_id`.

Bản này sửa để re-sync sẽ đưa class về term/block canonical. Nếu có class canonical sẵn thì class cũ được đánh dấu inactive/superseded.

### 4. Danh sách môn/lớp lấy cả class stale

Các query màn Môn/Lớp giờ lọc `AcademicClass.active = true` và `AcademicSubject.active = true`.

### 5. Course mapping chưa đúng ý “auto map nếu khớp”

Màn Môn giờ tự tạo mapping Course CMS khi:

```text
subject_code + term_run → tìm thấy đúng 1 CourseSyncState.course_id
```

Ví dụ:

```text
WEB107 + Summer 2026 → course-v1:FPT+WEB107+SU26
```

Nếu không tìm thấy hoặc có nhiều course trùng thì không tự map.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

Nếu server chưa chạy migration Academic trước đó:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production run --rm backend \
  alembic -c alembic.ini upgrade head
```

## Test bắt buộc sau deploy

```text
/semesters
/ap-sync
/student-management
/student-management/subjects/{subjectId}/classes
/student-management/classes/{classId}
```

Thứ tự kiểm tra:

1. `/semesters` vẫn chỉ có 2 block cho kỳ.
2. Chạy `/ap-sync` theo hệ Poly hoặc PTCĐ.
3. Vào `/student-management`, chọn đúng kỳ vừa sync.
4. Môn phải xuất hiện đúng theo quyền/phân công.
5. Bấm `Xem lớp`, lớp phải xuất hiện đúng.
6. Bấm `Chi tiết lớp`, sinh viên phải xuất hiện.
7. Nếu course đã được sync về AI Server và khớp duy nhất, trạng thái Course CMS ở màn môn phải là `Đã auto map Course CMS`.
