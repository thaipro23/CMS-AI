# v25.9.16.5.11 — Open edX Connector User Password & Final Hardening

## Mục tiêu

Dọn các điểm còn dễ gây lỗi trong luồng Student Progress CMS Sync sau khi course mapping, HMAC/CSRF và datetime JSON đã ổn:

1. Làm rõ chính sách mật khẩu khi `openedx_connector_plugin` tự tạo user CMS/Open edX.
2. Không tạo mật khẩu mặc định yếu hoặc lộ mật khẩu qua API/audit log.
3. Dùng thống nhất env `AI_CONNECTOR_*` trong plugin, không phụ thuộc tên cũ `AI_STUDENT_INSIGHT_*`.
4. Trả trạng thái password policy trong response để AI Server/job dễ chẩn đoán.

## Mật khẩu user CMS được tạo mới

Mặc định production:

```env
AI_CONNECTOR_CREATED_USER_PASSWORD_MODE=unusable
AI_CONNECTOR_CREATED_USER_DEFAULT_PASSWORD=
```

Nghĩa là user được tạo trong Open edX với `is_active=True` nhưng **không có mật khẩu local dùng để đăng nhập** (`set_unusable_password`). User vẫn dùng được cho enrollment, Course Staff, progress/grade tracking. Đăng nhập thật nên đi qua SSO hoặc reset password.

Nếu UAT bắt buộc có mật khẩu tạm để đăng nhập local, cấu hình trong Tutor/Open edX:

```bash
tutor config save --set AI_CONNECTOR_CREATED_USER_PASSWORD_MODE=fixed
tutor config save --set AI_CONNECTOR_CREATED_USER_DEFAULT_PASSWORD='<temporary-password-min-8-chars>'
tutor local restart lms cms lms-worker cms-worker
```

Không khuyến nghị dùng mật khẩu chung trong production. API không trả mật khẩu ra response.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

Cần cập nhật `openedx_connector_plugin` vào Open edX LMS/CMS giống các bản 5.8–5.10, sau đó rebuild/restart LMS/CMS nếu plugin được bake vào image.

## Ghi chú bảo mật

- Không trả mật khẩu trong API response.
- Audit log của AI Server đã mask các key chứa `password`.
- Nếu bật `fixed`, chỉ dùng UAT/import ngắn hạn và đổi sang `unusable` sau khi hoàn tất.
