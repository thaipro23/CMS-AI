# RUN v25.9.16.5.86 — StudentModule Progress Fallback + Active Connector Diagnostics

## Mục tiêu

Bản này sửa lỗi AI Server hiển thị `Course completion = N/A` dù trong Django shell LMS đọc được `StudentModule`:

- `completed_blocks=15`
- `total_blocks=70`

Sau v86, connector HTTP active trên LMS phải trả được:

- `progress_source=StudentModule` khi Course Home Progress official không khả dụng.
- `completed_blocks`
- `total_blocks`
- `progress_percent = completed_blocks / total_blocks * 100`

Backend AI Server sẽ lưu các field này vào `academic_student_learning_snapshots` thay vì để `NULL`.

## Deploy AI Server

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

Bản này không thêm migration mới.

## Deploy / restart connector LMS

Quan trọng: lỗi hiện tại có thể do LMS đang chạy cache module connector cũ. Sau khi copy/cài plugin mới, phải restart LMS.

Ví dụ với Tutor local:

```bash
tutor local restart lms cms
```

Nếu dùng Docker compose Tutor trực tiếp, restart container LMS/CMS tương ứng.

## Kiểm tra LMS đang dùng connector mới

Chạy trong LMS:

```bash
tutor local run lms python - <<'PY'
import importlib
m = importlib.import_module('openedx_ai_connector.student_insight')
print('file=', getattr(m, '__file__', None))
print('CONNECTOR_VERSION=', getattr(m, 'CONNECTOR_VERSION', None))
PY
```

Kết quả cần thấy:

```text
CONNECTOR_VERSION= 25.9.16.5.86
```

Nếu vẫn là version cũ hoặc không có `CONNECTOR_VERSION`, nghĩa là LMS chưa nhận code connector mới hoặc chưa restart đúng container.

## Kiểm tra đường HTTP connector active từ AI Server

Chạy trong backend container AI Server, thay `COURSE_ID` và `USERNAME` bằng dữ liệu thật:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend python - <<'PY'
from app.services.openedx_student_insight import OpenEdXConnectorClient

COURSE_ID = 'course-v1:FPT+COM1071+SU26'
USERNAME = 'duongddph69321'

client = OpenEdXConnectorClient()
print('base_url=', client.base_url)
print('class_analytics_endpoint=', client.class_analytics_endpoint)

data = client.class_analytics_payload(
    course_id=COURSE_ID,
    students=[{'username': USERNAME, 'student_code': USERNAME}],
)
print('diagnostics=', data.get('diagnostics'))
print('learning_counts=', data.get('learning_counts'))
for row in data.get('results') or []:
    print({
        'username': row.get('username'),
        'enrollment_status': row.get('enrollment_status'),
        'progress_source': row.get('progress_source'),
        'progress_percent': row.get('progress_percent'),
        'completed_blocks': row.get('completed_blocks'),
        'total_blocks': row.get('total_blocks'),
        'progress': row.get('progress'),
    })
PY
```

Kỳ vọng khi Course Home Progress không lấy được nhưng StudentModule có dữ liệu:

```text
progress_source: StudentModule
progress_percent: 21.43
completed_blocks: 15
total_blocks: 70
```

Với `15/70`, progress phải là `21.43%`.

## Chạy lại Cập nhật điểm / Đồng bộ full CMS

Ở màn chi tiết lớp:

- **Đồng bộ full CMS**: tạo/check user, check enroll, lấy progress/điểm.
- **Cập nhật điểm**: chỉ đọc progress/điểm; không tạo user, không enroll.

Sau khi chạy xong, box **Chẩn đoán điểm CMS** cần hiện:

- `StudentModule fallback > 0` nếu đang dùng fallback.
- `Course completion TB` không còn `N/A` nếu connector trả `completed_blocks/total_blocks`.

## Kiểm tra DB snapshot

Có thể kiểm tra nhanh trong backend container:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend python - <<'PY'
from app.db.session import SessionLocal
from app.models.academic import AcademicStudentLearningSnapshot

db = SessionLocal()
try:
    row = db.query(AcademicStudentLearningSnapshot).filter(
        AcademicStudentLearningSnapshot.completed_blocks.isnot(None),
        AcademicStudentLearningSnapshot.total_blocks.isnot(None),
    ).order_by(AcademicStudentLearningSnapshot.updated_at.desc()).first()
    if not row:
        print('Không thấy snapshot có completed_blocks/total_blocks')
    else:
        print('class_id=', row.class_id)
        print('student_id=', row.student_id)
        print('course_id=', row.openedx_course_id)
        print('completed_blocks=', row.completed_blocks)
        print('total_blocks=', row.total_blocks)
        print('progress_percent=', row.progress_percent)
        print('raw_source=', (row.raw_json or {}).get('payload', {}).get('progress_source'))
        print('raw_progress=', (row.raw_json or {}).get('payload', {}).get('progress'))
finally:
    db.close()
PY
```

## Lưu ý xử lý lỗi

Nếu Django shell LMS đọc được StudentModule nhưng HTTP connector vẫn trả `progress={}`:

1. Kiểm tra `CONNECTOR_VERSION` trong LMS có đúng `25.9.16.5.86` không.
2. Restart LMS/CMS.
3. Kiểm tra AI Server đang gọi đúng `OPENEDX_CONNECTOR_BASE_URL` trỏ tới LMS active, không trỏ nhầm CMS/host cũ.
4. Chạy lại lệnh HTTP connector từ backend container.

Nếu `total_blocks` vẫn null, cần kiểm tra modulestore/course structure trong LMS vì fallback cần đếm tổng block từ course tree.
