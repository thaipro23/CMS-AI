# v25.9.16.4.8 — AP Sync Idempotent Upsert & Duplicate Class Guard

## Mục tiêu

Hotfix cho lỗi đồng bộ AP khi chạy lại nhiều lần trong cùng một kỳ/cơ sở/môn:

- Nếu dữ liệu AP không đổi, backend giữ nguyên bản ghi và không update `updated_at` vô ích.
- Nếu dữ liệu AP thay đổi thật, backend mới update bản ghi liên quan.
- Tránh `UniqueViolation` tại `uq_academic_classes_term_block_subject_code` khi AP class đã tồn tại theo natural key nhưng một row cũ/stale có cùng `ap_class_id` đang được update sang key đó.
- Tránh lỗi dây chuyền `This Session's transaction has been rolled back...` bằng savepoint theo từng class.

## Thay đổi chính

### 1. Idempotent update cho AP sync

File chính:

```text
backend/app/services/ap_academic_sync.py
```

Các entity sau chỉ được ghi DB khi giá trị thật sự thay đổi:

- `academic_terms`
- `academic_blocks`
- `academic_subjects`
- `academic_teachers`
- `academic_students`
- `academic_classes`
- `academic_teacher_assignments`
- `academic_class_students`

Repeated sync cùng dữ liệu sẽ không còn tạo loạt `UPDATE ... SET updated_at = now()` trên hàng chục nghìn bản ghi.

### 2. Guard duplicate class natural key

Natural key của lớp vẫn là:

```text
term_id + block_id + subject_id + class_code
```

Khi sync gặp cả hai row:

- row đúng theo natural key hiện tại
- row cũ theo `ap_class_id`

backend chọn row đúng theo natural key làm winner, merge quan hệ an toàn từ row stale sang winner, sau đó mark row stale inactive với metadata:

```json
{
  "superseded_by_class_id": "...",
  "superseded_reason": "duplicate_natural_key"
}
```

Không xóa cứng class cũ để tránh mất audit/history hoặc hỏng FK.

### 3. Merge quan hệ từ class duplicate

Khi mark class stale, backend merge/giữ an toàn các quan hệ:

- `academic_class_students`
- `academic_teacher_assignments`
- `academic_class_course_mappings`
- `academic_student_learning_snapshots`

Nếu winner đã có link tương ứng, link duplicate được bỏ để tránh unique conflict.

### 4. Savepoint theo từng class

Mỗi AP class được xử lý trong `self.db.begin_nested()` để nếu một class lỗi, session không bị hỏng toàn bộ run. Lỗi class được ghi vào `academic_sync_errors`, các class khác vẫn tiếp tục xử lý.

## Deploy

Không có migration DB.

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker
```

## Kiểm tra nhanh

Mở log:

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production logs -f --tail=0 backend worker
```

Sau đó bấm sync AP cùng kỳ/cơ sở/môn vài lần. Kỳ vọng:

- Không còn lỗi `duplicate key value violates unique constraint "uq_academic_classes_term_block_subject_code"`.
- Không còn lỗi dây chuyền `This Session's transaction has been rolled back...`.
- Lần sync lại cùng dữ liệu không làm thay đổi hàng loạt `updated_at`.
