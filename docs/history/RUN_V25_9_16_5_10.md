# v25.9.16.5.10 — Open edX Connector Datetime JSON Serialization Hotfix

This hotfix fixes class sync failures like:

```text
Object of type datetime is not JSON serializable
```

## Cause

After HMAC/CSRF issues were fixed, the connector could reach real Open edX runtime data. Some Open edX/Django objects include `datetime`, `date`, `Decimal`, UUID, opaque keys, or other object types in response payloads or in AI Server JSON audit/snapshot fields. Plain Python `json.dumps` and SQLAlchemy JSON columns cannot persist those objects directly.

## Fix

- Open edX `openedx_connector_plugin` now uses a connector JSON encoder for all `_json_response(...)` responses.
- The encoder supports Django's standard datetime/date/time/Decimal/UUID behavior and string-falls-back for opaque Open edX keys/model-like values.
- AI Server connector client now signs and sends JSON bodies with a safe default serializer.
- AI Server academic learning/enrollment snapshots now sanitize connector payloads before writing to JSON columns.
- Audit metadata redaction now also converts datetime/date/time/Decimal/UUID and unknown objects into JSON-safe values.
