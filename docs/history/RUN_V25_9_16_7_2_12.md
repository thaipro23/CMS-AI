# RUN v25.9.16.7.2.12 — AP Class Scope Identity Fix

## Mục tiêu

Sửa lỗi đồng bộ AP bị thiếu lớp khi nhiều lớp có cùng `class_code`/tên lớp nhưng khác cơ sở, hệ, kỳ, block hoặc môn.

Từ bản này, định danh lớp AP khi đồng bộ là full scope:

```text
branch + campus + term + block + subject + class_code
```

Không còn coi `class_code` hoặc tên lớp là đủ để gộp lớp.

## Vì sao cần migration

Schema cũ có unique constraint:

```text
term_id + block_id + subject_id + class_code
```

Constraint này làm hai lớp cùng mã/tên ở hai cơ sở khác nhau bị xem như trùng. Bản này drop constraint cũ và tạo unique index mới theo full scope có `campus` + `branch`.

Không reset DB. Không xóa volume.

## Kiểm tra constraint/index sau migration

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production exec -T postgres sh -lc 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" <<SQL
SELECT conname FROM pg_constraint WHERE conrelid = '\''academic_classes'\''::regclass ORDER BY conname;
SELECT indexname, indexdef FROM pg_indexes WHERE tablename = '\''academic_classes'\'' AND indexname LIKE '\''%scope%'
ORDER BY indexname;
SQL'
```

Kỳ vọng:

- Không còn `uq_academic_classes_term_block_subject_code`.
- Có `uq_academic_classes_active_scope_code`.
- Có `ix_academic_classes_scope_lookup`.

## Kiểm tra sau đồng bộ

```sql
SELECT
  branch,
  campus,
  term_id,
  subject_id,
  class_code,
  COUNT(*)
FROM academic_classes
WHERE active IS TRUE
GROUP BY branch, campus, term_id, subject_id, class_code
HAVING COUNT(*) > 1
ORDER BY COUNT(*) DESC;
```

Query trên chỉ nên ra dòng nếu thật sự có duplicate cùng full scope. Cùng `class_code` nhưng khác `campus` là hợp lệ.
