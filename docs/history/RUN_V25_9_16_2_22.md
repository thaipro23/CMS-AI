# Run v25.9.16.2.22 - API-first Academic Autofill

This version keeps the v25.9.16.2.21 logic hardening and adds API-first autofill for Academic Course CMS mapping.

## What changed

- AP sync already uses AP `/get-course` and `/get-data-cms`; this remains the primary source for subjects/classes/students.
- Subject → Course CMS auto-map now checks CMS/Open edX APIs when the course is not present in local `CourseSyncState`.
- The user should not have to sync the full course tree manually just to map `WEB107 + Summer 2026` to `course-v1:FPT+WEB107+SU26`.
- Auto-map still saves only when exactly one exact Course CMS match exists.

## Optional env

```env
OPENEDX_STUDENT_INSIGHT_COURSE_SEARCH_ENDPOINT=/api/ai-student-insight/v1/courses/search
OPENEDX_COURSES_SEARCH_ENDPOINT=/api/courses/v1/courses/
OPENEDX_LMS_BASE_URL=https://cms-test.poly.edu.vn
OPENEDX_OAUTH_BASE_URL=https://cms-test.poly.edu.vn
OPENEDX_CLIENT_ID=...
OPENEDX_CLIENT_SECRET=...
# or OPENEDX_ACCESS_TOKEN=...
```

The Student Insight course search endpoint is optional. If it is unavailable, AI Server falls back to the LMS Courses API.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

No new Alembic migration is required.

## Test

1. Open `/ap-sync`, sync AP for a term/branch.
2. Open `/student-management` and select the same term/branch.
3. Confirm subject rows show Course CMS mapping when the exact Course exists in CMS/Open edX, even if the course was not previously synced into AI Server.
4. If no exact match or multiple matches exist, the row must stay un-mapped and require review.
