# Single-worker ten-job trial

**Goal:** Allow ten class jobs in one bulk worker with ten prefork processes, after testing. Keep production defaults unchanged until an operator enables the trial.

**Architecture:** Daily enrollment/score dispatch uses the existing `ACADEMIC_BULK_SYNC_DISPATCH_WINDOW` setting (default 4, supported maximum 20). Snapshot/export coordinators retain their default four-slot window. A single bulk pod may run `CELERY_BULK_CONCURRENCY=10`; do not scale to five pods.

**Constraints:** Keep saved root/child IDs, frozen Poly/PTCD scope, retries, locks and current stage. Lowering the window prevents additional dispatch without cancelling submitted children. No automatic deployment, resume or production load test. Local simulated work cannot establish real LMS throughput or worker peak RAM; obtain production resource measurements before enabling ten on the existing 2 GiB pod.

**Tasks:**
1. Red/green tests for configurable ten-slot dispatch, global branch sharing, idempotency, maximum and rollback.
2. Run an isolated real Redis/Celery single-worker ten-process probe, explicitly separate from actual LMS/DB load validation.
3. Run backend regression checks, independent review and publish the code plus a trial runbook. Keep base manifests at concurrency 2 and replicas 1.
