# v25.9.15.6.16 - Multi Source Chunk Reference Hotfix

## Why

Questions can be grounded in more than one source chunk. The model may return:

```text
83dd01d2-81fe-4ffa-8f72-63eb8d24aa5e/page33;83dd01d2-81fe-4ffa-8f72-63eb8d24aa5e/page13
```

Older validation treated that whole string as one chunk id and marked the item as `invalid_source_chunk` even though each chunk exists.

## Deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production build --no-cache backend worker frontend

docker compose -f docker-compose.prod.yml --env-file .env.production run --rm backend alembic upgrade head

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend worker frontend
```

No database migration is required.

## Verify

Generate again or re-run the failed chapter. A question with multiple chunks in `source_chunk_id` should not become `draft_error` unless at least one of the individual chunk ids is truly missing.
