# RUN v25.9.16.7.2.26 — Production Audit Hardening

## Mục tiêu

Bản này harden các điểm còn rủi ro trước production test có kiểm soát:

- FE đọc đúng `business_permissions` từ `/api/rbac/me`.
- Worker healthcheck fail-closed, không báo healthy giả.
- Health detail endpoints yêu cầu quyền phù hợp.
- Auto map tất cả lưu scope đã duyệt và worker chỉ xử lý trong scope đó.
- Child `full_cms_sync` có advisory lock chống enqueue trùng khi nhiều người bấm cùng lúc.
- `/analytics/learning` tải Môn theo trang + debounce tìm kiếm, không load all subjects.
- Đồng bộ version FE/BE/footer qua `APP_VERSION` / `NEXT_PUBLIC_APP_VERSION`.
- Chuẩn hóa một số từ UI: `Tự động ghép Course CMS`, `Ghi danh CMS`, `Tác vụ nền`.
- Dọn tài liệu release: root chỉ giữ RUN hiện tại, lịch sử chuyển vào `docs/history`.

## Deploy

```bash
cd /opt/ai-server

unzip -o ai-server-openedx-v25.9.16.7.2.26-production-audit-hardening.zip -d /tmp/ai-server-v25.9.16.7.2.26

rsync -a --delete /tmp/ai-server-v25.9.16.7.2.26/ai_server_openedx_v25_9_16_7_2_26/ /opt/ai-server/

# Không có migration mới trong 2.26, nhưng giữ lệnh upgrade head để an toàn nếu server chưa lên 0051.
docker compose -f docker-compose.prod.yml --env-file .env.production build backend frontend worker beat

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate backend

docker compose -f docker-compose.prod.yml --env-file .env.production exec backend alembic upgrade head

docker compose -f docker-compose.prod.yml --env-file .env.production up -d --force-recreate frontend worker beat
```

Cập nhật `.env.production`:

```env
APP_VERSION=25.9.16.7.2.26
NEXT_PUBLIC_APP_VERSION=25.9.16.7.2.26
NEXT_PUBLIC_APP_ENV=production
```

## Kiểm tra sau deploy

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml --env-file .env.production ps

docker compose -f docker-compose.prod.yml --env-file .env.production exec backend alembic current

docker compose -f docker-compose.prod.yml --env-file .env.production logs -n 100 backend

docker compose -f docker-compose.prod.yml --env-file .env.production logs -n 100 worker
```

Worker phải healthy thật. Nếu Redis/Celery ping lỗi thì container worker sẽ unhealthy, không còn healthy giả.
