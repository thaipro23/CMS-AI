# Deploy v25.9.16.7.2.64.16.5.7 — CI/E2E & Container Hardening

Artifact:

```text
ai-server-openedx-v25.9.16.7.2.64.16.5.7-ci-e2e-container-hardening.zip
```

## 1. Sao lưu và giải nén

```bash
cd /opt/ai-server

# Sao lưu database theo quy trình vận hành hiện tại trước khi deploy.
mkdir -p /tmp/ai-server-64-16-5-7
unzip -q \
  ai-server-openedx-v25.9.16.7.2.64.16.5.7-ci-e2e-container-hardening.zip \
  -d /tmp/ai-server-64-16-5-7

rsync -a --delete \
  /tmp/ai-server-64-16-5-7/ai_server_openedx_v25_9_16_7_2_64_16_5_7/ \
  /opt/ai-server/
```

Không chạy `docker compose down -v`; không sửa tay `alembic_version`.

## 2. Cấu hình version

```env
APP_VERSION=25.9.16.7.2.64.16.5.7
NEXT_PUBLIC_APP_VERSION=25.9.16.7.2.64.16.5.7
```

Alembic head không đổi:

```text
0053_v25_9_16_7_2_64_16_5_4_diff_idempotency.py
```

## 3. Kiểm tra cấu hình Compose

```bash
cd /opt/ai-server

docker compose -f docker-compose.prod.yml \
  --env-file .env.production \
  config >/tmp/ai-server-compose-64-16-5-7.yml
```

Kiểm tra các service mới/được harden:

```text
runtime-init
migrate
backend
worker
worker-heavy
worker-analytics
beat
frontend
```

`runtime-init` cấp quyền cho volume `/app/.runtime`. `migrate` chạy Alembic một lần; backend và worker chỉ khởi động sau khi migration hoàn tất.

## 4. Build và triển khai

```bash
docker compose -f docker-compose.prod.yml \
  --env-file .env.production \
  build runtime-init migrate backend worker worker-heavy worker-analytics beat frontend

docker compose -f docker-compose.prod.yml \
  --env-file .env.production \
  up -d --force-recreate \
  runtime-init migrate backend worker worker-heavy worker-analytics beat frontend
```

Không chạy Alembic đồng thời trong từng API replica. Trạng thái migration:

```bash
docker compose -f docker-compose.prod.yml \
  --env-file .env.production \
  run --rm migrate alembic -c alembic.ini current
```

## 5. Kiểm tra sau deploy

```bash
docker compose -f docker-compose.prod.yml \
  --env-file .env.production \
  ps

docker compose -f docker-compose.prod.yml \
  --env-file .env.production \
  logs --tail=200 migrate backend worker worker-heavy worker-analytics beat frontend

./scripts/ci-e2e-container-hardening-report.sh /tmp/ci-container-hardening
./scripts/backend-runtime-name-audit.sh /tmp/backend-runtime-audit
./scripts/frontend-runtime-contracts-report.sh /tmp/frontend-runtime-contracts
./scripts/production-security-closure-report.sh /tmp/security-closure
./scripts/performance-worker-reliability-report.sh /tmp/performance-worker
```

Smoke-test tối thiểu:

- đăng nhập SSO cookie-only và đăng xuất;
- desktop/mobile sidebar;
- dialog focus, Escape và focus return;
- Bank, Quiz, Student, Teacher, Analytics, Jobs, Audit và RBAC;
- Celery queues `interactive`, `sync`, `generation`, `exports`, `analytics`;
- runtime volume vẫn ghi được file export và Celery Beat schedule;
- container backend/frontend chạy UID `10001` và root filesystem read-only.

## 6. CI

Workflow `.github/workflows/ci.yml` chạy:

- PostgreSQL/Redis integration và Alembic downgrade/re-upgrade;
- Python compile, Ruff fatal checks và current-contract tests;
- frontend ESLint, TypeScript và production build;
- Playwright desktop/mobile browser smoke;
- build production images, kiểm tra UID non-root và Compose resolved contract.

## 7. Rollback

Nếu cần rollback code:

1. dừng application services, không xóa volume;
2. phục hồi source artifact `.64.16.5.6`;
3. build và recreate application services;
4. giữ database ở migration `0053` vì `.64.16.5.7` không có migration mới;
5. xác minh runtime volume ownership vẫn là UID/GID `10001`.
