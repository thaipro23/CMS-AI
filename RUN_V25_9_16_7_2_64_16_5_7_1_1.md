# Run v25.9.16.7.2.64.16.5.7.1.1

## 1. Pull source

```bash
cd /opt/ai-server
git pull
```

## 2. Confirm UAT HTTP settings

```bash
grep -E '^(APP_ENV|AUTH_COOKIE_SECURE|ALLOW_INSECURE_UAT_HTTP|AUTH_COOKIE_SAMESITE|FRONTEND_NPM_VERSION)=' .env.production
```

Expected minimum:

```env
APP_ENV=uat
AUTH_COOKIE_SECURE=false
ALLOW_INSECURE_UAT_HTTP=true
AUTH_COOKIE_SAMESITE=lax
FRONTEND_NPM_VERSION=10.9.2
```

`FRONTEND_NPM_VERSION` is optional because Compose defaults to `10.9.2`, but keeping it explicit makes the UAT build reproducible.

## 3. Validate source hotfix

```bash
chmod +x scripts/uat-build-backend-health-hotfix-report.sh
./scripts/uat-build-backend-health-hotfix-report.sh
```

Expected: `10 pass, 0 fail`.

## 4. Build application images

Do not use `--no-cache` routinely. Git/Dockerfile/package changes already invalidate the required layers, while the BuildKit npm cache protects against repeated downloads.

```bash
docker compose \
  --env-file .env.production \
  -f docker-compose.prod.yml \
  build --pull \
  frontend backend worker worker-heavy worker-analytics beat runtime-init migrate
```

The frontend dependency stage pins npm `10.9.2` and retries `npm ci` up to three times. If an npm attempt fails, its log tail is printed directly in the Docker build output.

## 5. Run migration job

There is no new migration in this hotfix, but run the canonical migration service so deployment state is verified:

```bash
docker compose \
  --env-file .env.production \
  -f docker-compose.prod.yml \
  run --rm migrate
```

Do not edit `alembic_version` manually and do not delete database/runtime volumes.

## 6. Recreate application services

docker compose \
  --env-file .env.production \

  up -d --force-recreate \

## 7. Verify status

```bash

  --env-file .env.production \
  -f docker-compose.prod.yml \
  ps -a

docker logs ai-backend --tail=250
```

Inspect backend health attempts when needed:

```bash
docker inspect ai-backend \
  --format '{{range .State.Health.Log}}{{println .End "exit=" .ExitCode .Output}}{{end}}'
```

Direct health check from inside the container:

```bash
docker exec ai-backend python -c "import http.client; c=http.client.HTTPConnection('127.0.0.1',8000,timeout=5); c.request('GET','/api/health'); r=c.getresponse(); print(r.status, r.read().decode())"
```

Expected HTTP status: `200`.

## 8. Important behavior

A legacy `/app/.runtime/runtime-settings.json` may contain old values such as demo auth or mock integrations. In UAT/production, the hotfix ignores those environment-owned fields automatically. Do not delete the `runtime_data` volume merely to clear them.
